## Requirements

Linux (x86_64) with [Nix](https://nixos.org/download) and flakes enabled
(`experimental-features = nix-command flakes`). Supply your own retail
`DDS.EXE` and MSVC 5.0 SP3 toolchain outside this repository. By default,
the development shell looks for them under ignored `build/local/`; set
`GITEN_RETAIL_EXE` and `GITEN_TOOLCHAIN` to use other local paths.

## Quickstart

```sh
nix develop          # one shell: MSVC 5.0 under Wine plus every analysis tool
giten init           # the build Wine prefix (also run on shell entry)
giten build          # compile and compare every unit
giten match range    # the matching loop: one unit in a few seconds
giten build verify   # the MAX gate and gate tiers, before a merge
giten sema -h        # navigate the retail image (xref, disasm, rva, class, ...)
```

The report lands at `build/objdiff/compare-new/report.json`;
`giten verify status` prints the per-function scores. Read next:
[documentation index](docs/README.md), [build system](docs/build-system.md),
[relocations](docs/relocations.md), [tooling map](docs/tooling-map.md), and
[AGENTS.md](AGENTS.md) for the rules.

## The pipeline

```
DDS.EXE + config/retail/reloc_sites.tsv -> build/exe/DDS.EXE (synthesized .reloc)
src/ labels + config/retail/  -> claims -> the Model (build/gen/bindings.tsv)
                              -> synthetic PDB -> vostok-delinker -> retail "target" objs
src/*.c                       -> MSVC 5.0 under Wine -> "base" objs
base vs target                -> objdiff report -> CUR, MAX and HIST per function
```

DDS.EXE was linked `/FIXED`, so it carries no relocations; the reviewed site
set in `config/retail/reloc_sites.tsv` stands in for them
([docs/relocations.md](docs/relocations.md)). The delink half reruns only when
labels change. `giten match <unit>` runs the whole chain for one unit;
`giten build` runs it for all; `giten build verify` adds the gates.

## Repo layout

```
src/            reconstructed C (plus the platform layer's C++), grouped by retail compiland
include/        shared headers; rva.h holds the address annotations
config/         units.toml (build manifest), match_baseline.tsv (scores), retail/ labels
scripts/giten/  the `giten` CLI and pipeline
docs/           usage and contracts; start at docs/README.md
AGENTS.md       the agent guide (CLAUDE.md links to it); skills in .agents/skills/
build/          all generated state (gitignored)
```

The pipeline is gruntz main at `26bb3e9da`
([sushi-shi/gruntz-decomp](https://github.com/sushi-shi/gruntz-decomp)), adapted
to this image: `/ML` + LIBC.LIB instead of MFC, a non-incremental `/FIXED` link,
and the import tables inside `.rdata`.

## Link status

Linking is opt-in: `giten link` produces `build/exe/DDS.candidate.EXE` and
its `.map`, and `giten verify check --tier link` audits it for unresolved
externals, the section table against retail's, and every 100% function's bytes
at its link-assigned address. See [`docs/image-diff.md`](docs/image-diff.md).

## Local candidate and resources

`giten link` reads the original EXE named by `GITEN_RETAIL_EXE`, writes an
ignored `build/gen/retail.res`, and links those resources into
`build/exe/DDS.candidate.EXE`. All 446 resource identities and payloads were
verified against the local original. The generated resource file is ignored;
no resource payload is tracked. The candidate also needs any game files stored
outside the EXE.

To build it, set the original EXE path before entering the shell:

```sh
export GITEN_RETAIL_EXE=/absolute/path/to/original/DDS.EXE
nix develop
giten link
```

To launch it, use an installed game directory containing the external `et/`,
`fc/`, and other game files. The original game's `DevConfig` binary value must
also contain valid device settings under `HKCU\Software\ASCII\GITEN_DDS`
in the runtime environment; without it `WinMain` exits before creating a
window. Use the original installation and configuration process; an arbitrary
binary value only bypasses the presence check. Run from that directory:

```sh
cd /path/to/game-directory
wine "$GITEN_DIR/build/exe/DDS.candidate.EXE"
```

Correct rendering and gameplay have not been validated. Both the original
and candidate show display problems in the current Wine setup. See
[runtime prerequisites and validation](docs/runtime-validation.md) before
treating a successful launch or matching screenshots as a working game.
