# Character function matching

These character functions still have compiler-shape differences after
their calls, referents and behavior were checked. Keep source validity and
retail side effects ahead of a higher fuzzy score.

| `0x03e3c0` | `PollTextPartySlotSelection` | Scoping `lineStep` to the sole branch that uses it restores the 99.4558% bank with 149 instructions, 15 calls, 12 branches, four returns, and 36 ordered referents, matching retail's counts. It removes the extra sign-extension move after `GetTextPlaneLineStep` without changing the `CopySkillList` declaration's correct `SkillList.h` owner. At `+0xd1`, retail keeps the `TextPlaneCellAt` word-start column in `edi` and selection mode in `ebx`; current MSVC keeps the column in `ebx` and mode in `edi`. The separate `i16` output cell column is unused; the `i16` output row drives the slot index and highlight. Prior output-width and sentinel probes changed the contract or highlight behavior. No retail callers have been recovered. |
| `0x03e6d0` | `AddCondition` | All 87 calls, 60 branches, 32 returns, and 123 ordered referents agree. The canonical object's successful condition-age store swaps the equivalent x86 base/index encoding (`[esi+eax+5]` versus retail's `[eax+esi+5]`); this is one differing SIB byte in addition to the return-tail differences. Eight blocked exits in the poison, ice, doze and tipsy escalation cases branch to the shared return in the vampire/injury cases in retail; current MSVC selects another identical blocked-return tail. The result remains `CONDITION_ADD_BLOCKED` on each path. Loop, goto, nested-if and case-order forms already tested do not recover this tail choice. Scoping the reset `blocked` accumulator to its single escalation-loop iteration makes its lifetime explicit and preserves the complete normalized `character.obj` byte-for-byte (SHA-256 `4b0b47112b14dd0004b8cc817bc287af6ec3977d9095b9471ea72f1a043a6cab`); the source-hash MAX reset from 99.94% to 99.93% is tracked in `syntactic-recovery.tsv`. |
| `0x0413f0` | `ApplyMoonPhase` | Retail saves `esi` before its null check, restores it on the null return, and computes `character->personalFlags` only after that check. Current MSVC defers the save until the pointer is needed. Both objects have ten calls, six branches, two returns, and ten ordered referents; retail has 73 instructions and current has 72. The remaining prologue byte also reverses the final `esi`/`edi` pop order. Wrapping the body in a non-null guard saved `esi` early but merged two retail returns into one; widening the change counter or returning it on the null path did not help. Reordering the `changed` and `flags` declarations, or placing the flags pointer in a new block after the null guard, compiled the complete `character` object byte-identically and left the late save. Separating the `changed` declaration from its zero assignment also preserved the code and was reverted for clarity. Replacing raw bitset calls with the existing typed `TestCharacterFlag`, `ClearCharacterFlag`, and `SetCharacterFlag` helpers preserved all bytes before the COFF symbol table (`0x8d43`); only symbol metadata changed. The typed helper source is retained and still checks for null before accessing a member. An older source revision computed the flags pointer before the check and scored higher, but that ordering cannot justify evaluating a member address on a null character. `ApplyClockChanges` can pass an empty party slot here, so the guard is live. Qualifying the by-value moon phase input `const` preserves the complete normalized `character.obj` byte-for-byte (SHA-256 `4b0b47112b14dd0004b8cc817bc287af6ec3977d9095b9471ea72f1a043a6cab`) and leaves the live null guard and two returns unchanged. |
| `0x010db0` | `AlignmentConflicts` (`fieldobj`) | All six calls, seven branches, four returns and six ordered relocations match. Retail saves the first alignment-class result in `esi` before loading the second argument into `ax`; current MSVC loads that argument into `cx` before saving the result. The B-class path similarly exchanges the argument and sum scratch registers. Using separate A/B class locals preserved the 0x8e-byte, 55-instruction shape but lowered the score from 84.64 to 84.45, so the probe was restored. `GetAlignmentClassA/B` read the proven signed byte members at `+0x7b/+0x7a`; no type or branch change is supported by this residue. |
