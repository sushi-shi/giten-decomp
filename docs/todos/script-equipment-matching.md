# Script and equipment matching boundaries

These functions have reconstructed behavior but still need a source shape that
reproduces the retail instructions. Use `giten walls diagnose <rva> --asm` and
the matching loop for live scores; the observations below are retail control
flow and caller contracts, not score checkpoints.

| Function | Retail evidence | Remaining source question |

| [OpNextChoice](../../src/Script/scriptvars.c) (`0x03a870`) | The choice cursor is saved before `GetTextPlaneSize`. The choice walk advances that one cursor to null; later scrolls reload the exhausted cursor. Both signed divisions in each coordinate calculation use one column count. Separating the grid's 32-bit column and row indices restores the two cursor-reload blocks: current and retail now both have 98 instructions, nine calls, six branches, one return, and 23 ordered relocations. The first difference moves to `+0xa`: current loads the choice cursor into ESI between saving ESI and EDI, while retail saves both first and loads the cursor into EDI. Current then keeps line step in EDI where retail uses ESI. | The source now reproduces the cursor entry, inner back edge, and later-scroll reload without restarting the list. The loop's column-count snapshot is `const` and compiles byte-identically. The remaining register assignment needs a supported source or translation-unit lifetime; swapping the row/column declaration order and moving the line-step declaration compiled byte-identically. A named current-node temporary in the choice walk also compiled byte-identically and was removed as redundant. Marking the line-step snapshot `const` preserves the complete `scriptvars.obj` byte-for-byte (`5fd03e4c2ce2e7dae98d3771defba1be6e798b63f184b67c3aca3173a6baa19c`) and is retained. Reversing the row multiplication operands compiled identically, so it was restored for readability. Grouping the output X and Y as a `TextPoint` lowered the match to 70.40% by changing codegen and was reverted; the API takes two scalar coordinates. |
| [OpIfEventObjectIs](../../src/Script/scriptfield.c) (`0x032560`) | Both objects have 24 instructions, three calls, four branches, one return, and five ordered relocations. Both load `g_actorId` first and `g_targetId` second. At `+0xe`, retail uses `dx` and `si` for those IDs and `ecx` for the predicate; current uses `cx`, `dx`, and `esi`. Both compare the two IDs twice, with the same branch edges and call arguments. The adjacent exact [OpIfBattleResult](../../src/Script/scriptfield.c) also holds its predicate in `ecx`, but needs only one global value (`g_targetCount` in `dx`), so it does not establish a shared two-ID lifetime. The shared `ScriptBooleanMatches` spelling compiles byte-identically. Naming the equality as a `const b16` snapshot before the predicate dropped the Event match from 97.92% to 39.79%; the snapshot was reverted because it removes the retail-shaped repeated comparison. | Identify a legitimate source lifetime or compiler state that selects the retail registers while retaining both comparisons and their ordered global loads. |
| [OpIfStatusPositive](../../src/Script/scriptfield.c) (`0x032660`) | Retail and current each have 20 instructions, two calls, four branches, one return, and three ordered relocations. At `+0x6`, retail loads status into `dx` and uses `ecx` for the predicate; current loads it into `cx` and uses `edx` for the predicate. The positive and none tests have the same branch destinations and call arguments. The named status snapshot is immutable; adding `const` leaves the entire `scriptfield` object byte-identical to the original (`ee9fd6054d20e75ca76a6d6ce48e4a206fa33b26bb827fa85cc352eef01bac8f`). A nested positive-status branch followed by a zero-status `else if` reduced the match to 43.25%; initializing the predicate directly from the expression lowered it to 51.95%. Those shapes were restored. | Identify the source or translation-unit state that selects the retail registers while retaining the positive/none distinction for negative status values. |

| [PollScriptPanels](../../src/Script/scripttext.c) (`0x02f070`) | All 87 instructions have matching mnemonic counts, and calls, branches, immediates, displacements, and ordered referents agree. Retail holds the panel count in `esi` and the last panel in `edi`; the current object swaps them. Scoping the row to the polling loop and the copied jump to the selected-row branch compiles byte-identically. Marking that packed jump copy `const` preserves its snapshot across `CallScript` and also compiles byte-identically. Qualifying both traversal pointers `const ScriptPanel*` also preserves the whole normalized `scripttext.obj` byte-for-byte (SHA-256 `65dccd3fb4fac4245f64b4911a9ab2ab59557301056a7c08f368c2da22bbc8e9`); polling only reads the list nodes while updating panel state through their mutable `Panel*` members. Other panel traversals call `ListLast` or draw every node, while this one needs both the tail and its count in one walk; adding `ListLast` would add a call absent from retail. An explicit `while` traversal and an inline `GetNextScriptPanel` accessor applied to all four script-panel walks also leave this body at 99.14%; the accessor was removed because it has no independent source witness. | Identify a supported panel traversal boundary or translation-unit state that recovers the register assignment without changing the walk or the selected row. |
| [PollEquipPart](../../src/Game/statuspanel.c) (`0x044fb0`) | A negative mode sets all of `eax` to `-1`, stores `ax` into the selected-part word, and returns directly before loading `member`; the final reset stores an immediate `-1` and sets only `ax` before its return. Mode 100 enters the final unhighlight/reset path. Invalid coordinates, an excluded part, and an active curse converge on that path. Selecting the already highlighted part returns without resetting it. Retail has 130 instructions, five calls, 19 branches, four returns, and 16 relocations; current has 123 instructions, five calls, 19 branches, three returns, and 15 relocations. | MSVC merges the negative-mode reset with the final reset. The `else if` mode dispatch is byte-identical and retained for clarity. Scoping the coordinate and part locals to the polling arm also compiled byte-identically and is retained. Inverting the outer guard, returning the stored global, returning the assignment from either or both reset sites, initializing the part local to the sentinel, putting the early reset in an inline helper, and using `part` as the early result carrier all compiled to the same object and were reverted. A scoped `cleared` result also retained three returns and 93.97%; widening that scoped reset result to `i32` still retained three returns and 93.97%, so both were reverted. Recover a source-level boundary that retains the entry store through `ax` and direct return for every negative mode. Callers pass `EQUIP_PICK_RESET`, `EQUIP_PICK_PART`, `EQUIP_PICK_ATTACH_TARGET`, or `EQUIP_PICK_CLEAR`; the retail signed comparison also defines behavior for other negative values. |

| [RunEquipScreen](../../src/Game/statuspanel.c) (`0x042e60`) | Both objects have the same call, branch, return, and ordered-referent sequences. The opening key handling and both bag-count clamp bodies agree. After the second clamp, retail loads the equipment pick into `cx` and the two `ItemSlot`/count words into `edx` and `eax`; current MSVC uses `ax`, `ecx`, and `edx`. On the same-ammo finish path, current MSVC stores and reloads the 16-bit member argument through a stack home before the inlined finish call, while retail pushes its argument register directly. Grouping the two `ItemSlot` declarations is byte-identical and retained for clarity. Scoping `loaded` to the same-ammo arm changed the object but left the 98.45% match unchanged, so it was reverted. Naming the gun-removal pick as `EQUIP_PART_AMMO` made the whole object byte-identically clearer. The menu `part`, equip `count`, and same-ammo immutable `loaded` are now declared in their respective switch arms. Per-unit comparison still reports 98.45% with the same 490 instructions, 68 calls, 28 branches, 11 returns, and 139 relocations. A raw COFF comparison against the prior object differs only in five ASCII digits of `$L` local label names; code and relocation bytes are identical. The old non-const `loaded` scope probe changed the object, whereas direct const initialization in its arm does not change code. Splitting the shared `slot` into separate equip, preview-remove, and remove-arm locals lowers similarity to 95.47%, so the single aggregate local remains. | Trace the aggregate copy and argument lifetime from the bag/equipment producers before changing the source order or storage model. |
