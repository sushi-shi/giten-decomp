# Script and equipment matching boundaries

These functions have reconstructed behavior but still need a source shape that
reproduces the retail instructions. Use `giten walls diagnose <rva> --asm` and
the matching loop for live scores; the observations below are retail control
flow and caller contracts, not score checkpoints.

| Function | Retail evidence | Remaining source question |
| --- | --- | --- |
| [OpNextChoice](../../src/Script/scriptvars.c) (`0x03a870`) | The choice cursor is saved before `GetTextPlaneSize`. The choice walk advances that one cursor to null; later scrolls reload the exhausted cursor. Both signed divisions in each coordinate calculation use one column count. Retail has 98 instructions and six branches versus the current 93 and four. After the first Y comparison, retail jumps over a back-edge cursor reload to a separate null test, then jumps over another reload into the walk body; the inner back edge stores the advanced cursor and revisits that reload. | The source preserves the cursor behavior but MSVC merges those entry and back-edge blocks. A guarded `do` walk and an explicitly separated first coordinate calculation plus scrolling `while` both compile to the same current 88.72% body. A `for` iterator spelling is byte-identical to the prior `while` and retained for clarity. Recover an authentic cursor/iterator lifetime that explains the two retail reload sites without restarting the choice list on each scroll. |
| [OpIfEventObjectIs](../../src/Script/scriptfield.c) (`0x032560`) | Calls, branches, stores, immediates, and ordered referents agree. Retail holds the two actor IDs in `dx` and `si`, and the predicate in `ecx`; the current object uses `cx`, `dx`, and `esi`. The shared `ScriptBooleanMatches` spelling compiles byte-identically. | Identify a legitimate source lifetime or compiler state that selects the retail registers. |
| [OpIfStatusPositive](../../src/Script/scriptfield.c) (`0x032660`) | Calls, branches, stores, immediates, and ordered referents agree. Retail holds status in `dx` and the predicate in `ecx`; the current object holds them in `cx` and `edx`. The named status snapshot compiles byte-identically. A nested positive-status branch followed by a zero-status `else if` preserved the predicate but reduced the match to 43.25%; initializing the predicate directly from the expression lowered it to 51.95%. The existing expression and assignment form was restored. | Identify the source or translation-unit state that selects the retail registers while retaining the positive/none distinction for negative status values. |
| [OpIfInBattle](../../src/Script/scriptfield.c) (`0x0326a0`) | Calls, branches, stores, immediates, and ordered referents agree. Retail holds battle state in `dx` and the predicate in `ecx`; the current object swaps them. Declaring the predicate before reading the invert flag lowered the match to 75.00%; the original lifetime was restored. | Identify the source or translation-unit state that selects the retail registers. |
| [PollScriptPanels](../../src/Script/scripttext.c) (`0x02f070`) | All 87 instructions have matching mnemonic counts, and calls, branches, immediates, displacements, and ordered referents agree. Retail holds the panel count in `esi` and the last panel in `edi`; the current object swaps them. Scoping the row to the polling loop and the copied jump to the selected-row branch compiles byte-identically and preserves the snapshot across script calls. An explicit `while` traversal and an inline `GetNextScriptPanel` accessor applied to all four script-panel walks also leave this body at 99.14%; the accessor was removed because it has no independent source witness. | Identify a supported panel traversal boundary or translation-unit state that recovers the register assignment without changing the walk or the selected row. |
| [PollEquipPart](../../src/Game/statuspanel.c) (`0x044fb0`) | A negative mode stores `-1` from `ax` and returns directly at entry; the final reset stores an immediate `-1`. Mode 100 enters the final unhighlight/reset path. Invalid coordinates, an excluded part, and an active curse converge on that path. Selecting the already highlighted part returns without resetting it. Retail has four returns; the current object has three. | MSVC merges the negative-mode reset with the final reset. The `else if` mode dispatch is byte-identical and retained for clarity. Inverting the outer guard, returning the stored global, returning the assignment from either or both reset sites, initializing the part local to the sentinel, and putting the early reset in an inline helper all compiled to the same object and were reverted. A scoped `cleared` result also retained three returns and 93.97%, so it was reverted. Recover a source-level boundary that retains the entry store through `ax` and direct return for every negative mode. Callers pass `EQUIP_PICK_RESET`, `EQUIP_PICK_PART`, `EQUIP_PICK_ATTACH_TARGET`, or `EQUIP_PICK_CLEAR`; the retail signed comparison also defines behavior for other negative values. |
| [ItemListMenuHandler](../../src/Game/statestack.c) (`0x01a240`) | The callback accepts `MENU_EVENT_DESTROY`, `MENU_EVENT_BEGIN_PAGE`, and `MENU_EVENT_ADD_ROW` from `SetMenuItems`. Both bodies have 142 instructions, 12 calls, 12 branches, four returns and 17 ordered relocations. Retail loads `menu` into `ebx` before saving `ebp`, then retains the loaded `ItemRecord*` in `ebp`; the current object keeps `menu` in `ebp` and the record in `ebx`. The swap persists through the final line writer and destroy arm. The retail row arm rereads the entry item after calls; the shared `GetItemListItem` accessor now names that repeated per-use read at all 12 sites in three translation units. Those three compiled objects are byte-identical to their pre-helper versions, leaving the prologue register swap as the first difference. | No missing event arm is indicated. A justified local or helper boundary would need to explain both pointer lifetimes; declaration and case-scope changes alone did not. Avoid caching the item across calls without evidence that those calls cannot change it. |
| [RunEquipScreen](../../src/Game/statuspanel.c) (`0x042e60`) | Both objects have the same call, branch, return, and ordered-referent sequences. The opening key handling and both bag-count clamp bodies agree. After the second clamp, retail loads the equipment pick into `cx` and the two `ItemSlot`/count words into `edx` and `eax`; current MSVC uses `ax`, `ecx`, and `edx`. On the same-ammo finish path, current MSVC stores and reloads the 16-bit member argument through a stack home before the inlined finish call, while retail pushes its argument register directly. Grouping the two `ItemSlot` declarations is byte-identical and retained for clarity. Scoping `loaded` to the same-ammo arm changed the object but left the 98.45% match unchanged, so it was reverted. Naming the gun-removal pick as `EQUIP_PART_AMMO` made the whole object byte-identically clearer. | Trace the aggregate copy and argument lifetime from the bag/equipment producers before changing the source order or storage model. |
